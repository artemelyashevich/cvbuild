# Задача: обновить фронтенд CV Builder под новые возможности бэкенда

Ты работаешь в репозитории фронтенда CV Builder (dev-сервер `http://localhost:3000`, бэкенд `http://localhost:8888`). Бэкенд (Spring Boot) уже изменён. Твоя задача — поддержать эти изменения на клиенте: голосовой диалог с моделью, отображение расхода токенов, обновлённые правила STOMP-чата и новые коды ошибок.

Прежде чем писать код:
1. Изучи структуру проекта: фреймворк, роутинг, стейт-менеджмент, HTTP-клиент, текущий STOMP/SockJS-клиент, работу с SSE, UI-кит. Пиши в стиле существующего кода и переиспользуй его утилиты, не заводи параллельные.
2. Найди, где сейчас используются `/test/{chatId}` (SSE), `/ws` + `/app/ai.interview` (STOMP), `/audio` (WebSocket) и `/api/v1/resume-flow`. Меняй именно эти места.
3. Если что-то в контракте ниже расходится с тем, что ты видишь в коде фронта, — остановись и опиши расхождение, не угадывай.

Авторизация на бэкенде — JWT в cookie `access_token` (HTTP и WebSocket-рукопожатие) или заголовок `Authorization: Bearer <token>`.

Ошибки REST приходят телом `{"message": "...", "errors": {...}}` (поле `errors` может отсутствовать) с HTTP-статусом из таблицы ниже.

## 1. Голосовой диалог с моделью (главная фича)

Пользователь говорит в микрофон, сервер распознаёт речь (Vosk), модель отвечает потоком, фронт озвучивает ответ через браузерный `speechSynthesis`.

### Подключение

```
ws://localhost:8888/audio?chatId=<uuid чата>
```
- Авторизация — cookie `access_token` (браузер отправит её сам, если домен/`SameSite` позволяют; проверь это в dev). Без аутентификации или без валидного `chatId` рукопожатие отклоняется.
- `Origin` должен совпадать с `app.security.allowed-origins` на бэкенде (по умолчанию `http://localhost:3000`).
- Эндпоинт существует только при `app.volk.enabled=true` на бэкенде. Если подключение не удалось — кнопку голоса скрой или сделай неактивной с подсказкой, не ломай текстовый чат.
- Чат должен принадлежать текущему пользователю, иначе ответ модели придёт как `error`.
- Кадры `ai_chunk`/`ai_sentence` после `cancel` или новой фразы ещё могут прийти с небольшой задержкой — игнорируй их, если пузырь уже помечен прерванным.

### Клиент → сервер

| Сообщение | Когда |
|---|---|
| Бинарные кадры: PCM 16-bit little-endian, моно, **16 000 Гц** | Пока пользователь говорит. Кадры по ~100–250 мс. |
| Текст `{"type":"stop"}` | Пользователь отпустил кнопку / нажал «Готово» — сервер завершит распознавание фразы. |
| Текст `{"type":"cancel"}` | Прервать текущий ответ модели (пользователь перебил). |

Захват аудио: `getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true, channelCount: 1 } })` → `AudioWorklet` (не `ScriptProcessorNode`) → ресемплинг из частоты `AudioContext` (обычно 48 кГц) в 16 кГц → `Float32` в `Int16` → `ws.send(buffer)`. `MediaRecorder` не подходит — он отдаёт сжатый webm/opus, сервер ждёт сырой PCM.

### Сервер → клиент (JSON-текст)

| `type` | Поля | Что делать |
|---|---|---|
| `partial` | `text` | Промежуточная расшифровка — показывать «живым» текстом, заменяя предыдущий `partial`. |
| `final` | `text` | Итоговая фраза пользователя — добавить в ленту чата как сообщение пользователя. |
| `ai_chunk` | `message` | Токен ответа модели — дописывать в текущий пузырь ответа. |
| `ai_sentence` | `message` | Готовое предложение, очищенное от markdown, — **только для озвучки**, не для отображения. Поставить в очередь `speechSynthesis`. |
| `ai_done` | `message: ""` | Ответ завершён. |
| `error` | `message` | Ответ не удался — показать ошибку в пузыре, прекратить ожидание. Сервер присылает общий текст `"AI response failed"` для любой причины (чужой чат, исчерпан лимит, сбой модели); после `error` запроси `/api/v1/user-stats/tokens` — если `remaining` = 0, покажи сообщение о лимите. |

Обрати внимание: у расшифровки поле `text`, у ответов модели — `message`.

### Озвучка и перебивание

- Каждое `ai_sentence` → `new SpeechSynthesisUtterance(text)` с `lang` из локали пользователя (`ru-RU` по умолчанию), `speechSynthesis.speak()` — браузер сам ставит их в очередь. Выбери голос под язык через `speechSynthesis.getVoices()` (событие `voiceschanged`).
- Пока модель говорит, не отправляй микрофон на сервер (иначе модель услышит сама себя) — либо дай режим «нажми и говори».
- Перебивание: если пользователь начал говорить или нажал «Стоп» во время ответа → `ws.send('{"type":"cancel"}')` + `speechSynthesis.cancel()` + пометить текущий пузырь как прерванный. Новая фраза `final` на сервере тоже сама отменяет предыдущий ответ.
- `speechSynthesis` требует жеста пользователя — первый `speak()` делай после клика по кнопке микрофона.
- При закрытии страницы/смене чата: `speechSynthesis.cancel()`, остановить треки микрофона, закрыть `AudioContext` и сокет.

### UI

Кнопка микрофона в поле ввода чата с состояниями: выключено → слушаю (индикатор уровня громкости) → модель думает → модель говорит (кнопка «Остановить») → ошибка. Переключатель «Озвучивать ответы» (сохранять в `localStorage`). Обработать отказ в доступе к микрофону понятным сообщением.

## 2. Расход токенов и тариф

```
GET /api/v1/user-stats/tokens
```
Ответ:
```json
{
  "plan": "FREE",
  "promptTokens": 1200,
  "completionTokens": 800,
  "used": 2000,
  "limit": 100000,
  "remaining": 98000,
  "periodStart": "2026-09-01T00:00:00",
  "resetAt": "2026-10-01T00:00:00"
}
```
- `plan` — `"FREE"` или имя активного тарифа (например `"PRO"`); это произвольная строка, не enum.
- Период — календарный месяц; `resetAt` — момент обнуления.
- Считаются только ответы чата (включая голосовые). Прерванные ответы списываются по оценке.

Сделать:
- Индикатор использования (прогресс-бар `used / limit`, «осталось N токенов, обновится <дата>») в профиле/настройках и компактно рядом с чатом.
- Бейдж тарифа; для FREE — место под будущий CTA «Перейти на PRO» (без реальной оплаты, кнопка может вести на заглушку).
- Обновлять данные после завершения ответа модели (`ai_done` в голосе, закрытие SSE-стрима), без поллинга по таймеру. В STOMP маркера конца ответа нет (в топик идут только токены) — обновляй, когда токены перестали приходить ~3 с, и перед отправкой следующего сообщения.
- Предупреждение при `remaining / limit < 10%`.
- Лимит исчерпан (проверка включается на бэкенде флагом): в SSE-чате приходит **429**; в голосе — `error`; в STOMP — ответа просто нет. Поэтому перед отправкой проверяй последний известный `remaining`, а при 429 / `error` / отсутствии ответа перезапрашивай `/tokens`. При `remaining` = 0 заблокируй поле ввода и покажи дату сброса из `resetAt`.

## 3. STOMP-чат (`/ws`, SockJS) — изменились правила

- **CONNECT обязан содержать заголовок** `Authorization: Bearer <access token>`. Без него сообщения в `/app/ai.interview` теперь молча игнорируются. Проверь, что токен передаётся в `connectHeaders`, и обнови его при переподключении после refresh.
- Отправка: `/app/ai.interview` с телом `{"chatId": "<uuid>", "content": "..."}`. Поле `userId` больше не нужно (сервер берёт пользователя из сессии) — убери его.
- Подписка на `/topic/chat/{chatId}` разрешена только на собственный чат; чужая подписка молча отбрасывается (данные просто не придут).
- Ошибки обработки сообщения (чужой чат, исчерпан лимит) сервер клиенту **не присылает** — ответ просто не начнётся. Поставь таймаут ожидания первого токена (~30–60 с) с сообщением «Не удалось получить ответ» и перезапросом `/tokens`.
- Новое сообщение в той же сессии **отменяет** незавершённый стрим предыдущего ответа. На клиенте: при отправке нового сообщения закрыть текущий пузырь ответа как прерванный, не склеивать токены двух ответов.
- Отключение сокета отменяет генерацию на сервере.

## 4. SSE-чат (`POST /test/{chatId}`, `text/event-stream`)

- Закрытие соединения (`AbortController.abort()`) теперь реально останавливает генерацию на сервере — используй это для кнопки «Остановить» и при уходе со страницы/смене чата.
- Новые статусы до начала стрима: **403** — чат принадлежит другому пользователю; **429** — лимит токенов. Статус надёжен, тело ошибки при `text/event-stream` может отсутствовать — не полагайся на него.

## 5. Конструктор резюме (`POST /api/v1/resume-flow`)

- Может ответить **504** («AI did not respond within …»), если модель не ответила за отведённое время (по умолчанию 2 минуты). Показать понятное сообщение и кнопку «Повторить», сохранив введённые данные формы.
- Запрос долгий: индикатор прогресса, блокировка повторной отправки, таймаут HTTP-клиента на фронте — больше серверного (≥ 150 с).

## Сводка кодов ошибок

| Код | Где | Значение |
|---|---|---|
| 403 | SSE-чат | Чужой чат |
| 429 | SSE-чат | Исчерпан месячный лимит токенов (`resetAt` — когда сбросится) |
| 504 | `/api/v1/resume-flow` | Модель не ответила вовремя |

В голосе те же ситуации приходят как `{"type":"error"}`, в STOMP — отсутствием ответа (см. выше).

## Требования к результату

- TypeScript-типы (если проект на TS) для всех новых сообщений и DTO: `VoiceServerMessage` (discriminated union по `type`), `TokenUsage`.
- Логика голоса — в отдельном модуле/хуке (захват аудио, ресемплинг, сокет, очередь озвучки), UI-компонент только использует его. Ресемплинг — чистая функция с юнит-тестом.
- Тесты в стиле проекта: разбор серверных сообщений голосового протокола, ресемплинг 48k→16k, отображение токенов и состояние при 429, отмена стрима при новом сообщении.
- Все ресурсы освобождаются при размонтировании (микрофон, `AudioContext`, WebSocket, `speechSynthesis`, SSE-запросы) — проверь отсутствие утечек при переключении чатов.
- Доступность: кнопки с `aria-label`, состояние записи озвучено для скринридеров, управление с клавиатуры.
- Тексты интерфейса на русском, через существующий механизм локализации, если он есть.

В конце перечисли: изменённые файлы, что проверено вручную (голос в Chrome и Firefox, 403/429/504), и что не удалось проверить.
